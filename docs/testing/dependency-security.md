Fresh isolated profiles and deterministic model/GitHub boundaries are mandatory. No automatic live
provider requests, account changes or owner stress trial. If an existing required failure is exposed,
retain it and diagnose within scope rather than waive it or increase thresholds/timeouts without
specific owner approval. The two bounded test-only exceptions recorded in the plan/results must
retain assertions, explicit short-expiry/takeover coverage and product deadlines. Regression
evidence does not establish native/VM or live provider compatibility unless those boundaries ran.

This maintenance task adds no UI layout. Connected existing journeys apply to runtime dependency
changes; documentation/workflow-only drafts do not need fabricated UI or agent-run reports.

DS01 also covers the completeness guard with empty/whitespace/nonempty snapshot warnings on every
page, malformed JSON/data,401/403, timeout and pagination boundary failures. It must request the same
immutable base/head as the vendor, retain safe comparison provenance and never forward a token to
another origin. A genuinely empty complete comparison is permitted; known positive/negative
dependency controls establish ingestion. Vendor failures and guard failures remain blocking.

DS01 additionally rejects truncated/noncanonical base64 and invalid UTF-8 warnings, ambiguous or
malformed Link headers, duplicate relations/query keys and missing next links. Quoted/unquoted
relations and quoted commas must preserve all pages. After the vendor runs, compare its complete
`dependency-changes` output to the guarded inventory using the pinned schema/defaults, preserving
scope omission, full advisory metadata and duplicate counts. A filtered vulnerable-only list is
insufficient. Test missing/empty/malformed output, row removal/addition, changed version/manifest/
scope/advisory metadata, skipped/failed normal analysis and legitimate complete empty comparisons.
For the negative control require vendor failure, complete inventory equality and the specific known
runtime/development advisory findings. Output-size or API limits remain failed qualification.

The first hosted inventory had171440 characters and exceeded Linux's per-environment-string limit.
The repaired transport uses the runner's Node custom shell with a standalone `toJSON` string literal,
then exclusive private files bounded at2MiB. No shell interpolation, bulk environment/argv, truncation
or filtered inventory fallback is allowed. Test adversarial strings, the observed large payload,
missing/malformed/truncated/private-file violations and exact complete inventory equality.
The runner's finite expression budget can still fail qualification; it is not bypassed.

The official-bundle fixture job verifies all three pinned runtime files by size, Git object ID and
SHA256 before execution. Children receive only a synthetic token and loopback API endpoint, with
bounded time/log/output capture and failure receipts. This proves vendor policy against deterministic
responses; it does not establish a live hosted negative dependency-graph comparison or an OS network
sandbox. The real forward PR comparison and complete independent inventory binding remain mandatory.
