# MCP onboarding verification plan

**Status:** planned, not executed. **Owner:** `agent-platform-mcp-onboarding`.  
**Contract:** [MCP-01 through MCP-08](../planning/mcp-onboarding-mvp.md).  
**Results:** [Planning critique and later execution evidence](../reviews/mcp-onboarding-planning.md).

## Environments, fixtures and evidence

Use real API, SQLite and MCP SDK/transport, with disposable synthetic keys and server configurations. Browser Playwright runs against Compose; Electron uses isolated user data and its actual native backend. Seed through supported APIs, then use accessible UI import/test/assignment/chat controls. Never mock the frontend/backend boundary under assessment. A deterministic external model HTTP double selects named tools; it does not prove real model quality or paid-provider compatibility.

Implement a tiny test-only protocol server with handshake/list/call, expected synthetic env/header authentication, effect journal, request IDs and explicit failure modes. Use separate ports and PIDs per test. Observe zero effects only after a settled denied/failed state, not a fixed sleep. Inspect disposable DB state independently of UI and preserve terminal evidence before cleanup. Test command paths with spaces and literal quotes. Protect fixture keys from artifacts; retain screenshots/traces, safe API result excerpts, DB redaction assertions, effect counters and final V1 diagnostic reports with request/run/operation correlation. Redact imported input from browser traces or disable secret-input capture for that interval and retain equivalent safe assertions.

Unit tests cover deterministic parsing, public/resolved schemas, header/env validation and error mapping. Integration tests cover encryption/migration, real transport and lifecycle. Browser/desktop tests cover actual user paths and persisted effects rather than repeating every parser combination in UI. No cloud/distribution or arbitrary-server sandbox tests are applicable because those capabilities are excluded.

## Commands and terminal gates

Use Node24 with normal hooks, canonical `WORKFLOW_GIT_BINARY=/usr/bin/git`, existing Vitest fork settings and tracing-off test environment. Build before execution. Run affected package unit/integration tests, `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, explicit formatting for new docs, direct Markdown validation and repository link checks. Add focused root Playwright MCP tests and desktop MCP tests, run via their existing configs/scripts; implementation records exact filenames and commands before sign-off. Use the existing Compose test service flow, not a new ad-hoc host API/web stack.

Final implementation review uses the actual changed source plus evidence. Inspect latest exact-head CI, security findings and review threads even when another job fails. Stage promotion later requires real protected full scan and actual packaged macOS VM success where required. Earlier unrelated green checks do not qualify this work. Do not claim source-tree Electron tests prove checkout-free distribution.

## Result schema and cleanup

For each V ID record revision, environment, fixture/upstream version, exact command, outcome (passed/failed/skipped/blocked/not run), UI observation, independent state/effect assertion, diagnostic IDs and artifact paths, limitations and repairs. Missing required evidence is inconclusive and blocks completion. Capture success as well as failure evidence. Teardown only owned fixture processes/ports, disposable DB/key/app-data and temporary Compose resources; never reset personal app data or paused worktrees. Limit identical transient retries to two, inspect failures and preserve original evidence; do not weaken the acceptance threshold.
