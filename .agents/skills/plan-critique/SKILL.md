# Plan critique

Use [documentation](../documentation/SKILL.md) and the canonical guide for artifact locations.
Read the [native developer policy](../../../docs/development/codex-development.md).

## Independent native review

Review substantive plans independently from their author. Use available native source/evidence tools;
do not edit the reviewed material, mutate Beads/Git/external state or dispose your own findings.
This read-only assignment is procedural; it does not establish technical inherited-tool isolation.
A custom no-tool route, isolated launcher, gateway/admission or persisted exact-material approval
is not required for ordinary developer review. No active-run discovery prerequisite.

The coordinator supplies owner scope/requirements, plan/manifest, real task specs/dependencies,
verification/DoD, source/branch and unresolved questions. Inspect actual relevant source instead
of trusting only the coordinator's summary. Request missing evidence when it cannot be obtained
within available permissions. Do not invent independent approval or accept your own plan.

## Review criteria and result

Check objective, non-goals, testable requirements, task/dependency order, delivery/branch mapping,
feasibility and environment access. Verify product/security preservation, meaningful relevant tests,
connected product journeys/independent effects where behavior changes, and final integration ownership.
Distinguish mocks, planned tests, actual evidence, native execution and prototype conformance.
Check that source documents/Beads/DoD agree, preserved work is safe and escalation is limited to
real owner-intent/behavior/delivery changes or reserved actions. Routine refinements do not need
another owner grant. Existing end-to-end authorization covers progression after critique correction.

Return a structured verdict and actionable findings with stable ID, severity, requirement and source
references. Use approved only with no actionable findings; correction_required for repairable gaps;
rejected for an unsafe/infeasible proposal; human_decision_required for an unresolved owner choice.
Recheck affected semantics independently after corrections; preserve findings/dispositions and source
revision. A review is not owner acceptance, merge or release authority.

Explicit PAUSED prototype runs retain their own machine review schema/approval controls in
[prototype planning](../../../docs/workflow-control-planning.md); do not loosen that runtime to make
native development work. No prototype/pilot resumption is implied by this skill.
